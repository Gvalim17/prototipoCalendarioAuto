## RF03 — Reutilização de Disciplinas (Autocomplete)

### Backend

**Novo endpoint:** `GET /disciplines/search?q=<query>`

- Busca disciplinas em todos os MBAs que contenham o termo (case-insensitive)
- Retorna: `[{ id, name, module_name, mba_name }]`
- Mínimo de 2 caracteres para disparar a busca

**Endpoint existente atualizado:** `POST /modules/{id}/disciplines`

- Ganha campo opcional `existing_discipline_id: int | None`
- Se informado: cria vínculo com disciplina existente (sem duplicar registro)
- Se não informado: comportamento atual (cria nova disciplina)

### Frontend (MBAList.tsx)

No formulário de adição de disciplina ao módulo:

1. Input de texto com debounce de 300ms
2. Ao digitar ≥ 2 caracteres, chama `GET /disciplines/search?q=<term>`
3. Dropdown abaixo do input lista resultados com contexto: `"Finanças Corporativas — Finanças / MBA Executivo"`
4. Selecionar item: preenche o nome, marca `existing_discipline_id`, campo fica read-only
5. Não selecionar / limpar: cria disciplina nova normalmente

## RF07/RF08 — Resolução Interativa de Conflitos

### Fluxo Geral

```
Step 1 (config) → confirmação → geração → Step 2b (resolução de conflitos, se houver) → Step 3 (calendário final)
```

### Backend

**Resposta ampliada do `POST /generate-schedule/`:**

```json
{
  "dates": [...],
  "skipped": [
    {
      "original_date": "2026-05-01",
      "reason": "Feriado: Dia do Trabalho",
      "suggested_date": "2026-05-08"
    }
  ]
}
```

`suggested_date` = próxima data válida no mesmo dia da semana após `original_date`.

**Novo endpoint:** `POST /schedules/resolve-conflicts/`

Payload:
```json
{
  "config": { ...mesmo payload de generate-schedule... },
  "resolutions": [
    { "original_date": "2026-05-01", "action": "auto", "resolved_date": "2026-05-08" },
    { "original_date": "2026-06-07", "action": "manual", "resolved_date": "2026-06-14" }
  ]
}
```

Retorno: cronograma final com todas as datas (originais + resolvidas) ordenadas, sem conflitos pendentes.

O gerador existente permanece intacto — a resolução é pós-processamento.

### Frontend (ScheduleForm.tsx)

**Step 2b — painel "Resolução de Conflitos":**

- Aparece automaticamente quando `skipped.length > 0` após geração
- Para cada conflito, um card exibe:
  - Data bloqueada + motivo: `"01/05/2026 — Feriado: Dia do Trabalho"`
  - Botão **"Ajuste Automático"** → pré-seleciona `suggested_date`
  - Date picker inline para **ajuste manual**
- O usuário pode misturar: auto em alguns, manual em outros
- Botão **"Aplicar Resoluções"** no rodapé:
  - Habilitado somente quando todos os conflitos têm data resolvida
  - Chama `POST /schedules/resolve-conflicts/`
  - Avança para Step 3 com o calendário final

**Step 3 (calendário):** igual ao Step 2 atual, sem sidebar de conflitos pendentes.
